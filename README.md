# 나의 근무

GitHub Pages용 개인 근무 달력입니다. 개인 데이터는 각 기기 브라우저의 IndexedDB에만 저장하며 서버와 유료 API가 필요하지 않습니다. 로그인, 동기화, 공유 기능은 없습니다.

## 실행
Node.js 설치 후 `npm run preview`를 실행하고 http://127.0.0.1:4173 에 접속합니다. 이 주소는 실행한 PC 전용입니다. `npm test`로 계산 검증을 실행합니다.

## 사용
왼쪽 메뉴에서 DIA 등록 또는 일정 등록을 선택합니다. 분석 요청문을 복사해 사진과 함께 AI 대화에 전달하고, 받은 JSON 파일을 가져옵니다. 앱 자체는 사진 분석이나 API 호출을 하지 않습니다. 미리보기를 확인하고 저장하세요. DIA 사진에는 날짜가 없어도 됩니다. 분석 파일에는 printed_year와 effective_from을 null로 둘 수 있습니다. 등록 화면에서 적용 시작일을 지정하며, 기존 일정 중 가장 이른 날짜(없으면 오늘)를 기본 제안합니다. 동일 날짜 일정은 교체됩니다.

날짜를 누르면 상단 카드가 해당 근무로 바뀝니다. 제목과 오늘 버튼은 오늘로 돌아갑니다. 휴무 코드도 원문 그대로 표시합니다. 설정·백업에서 주간 출퇴근 시각, 휴일 규칙과 공휴일 목록을 설정하고 전체 백업을 보관합니다. 주간 시각은 09:00~18:00으로 설정할 수 있습니다.

토·일요일에는 휴일표를 사용합니다. **평일 공휴일은 설정에 날짜를 추가해야 합니다.** 공휴일 자동 조회는 아직 없습니다.

## 예상 퇴근 잠정 계산
출근 + 원문 근무시간 + 휴게시간으로 계산합니다. 당일 근무는 60분, 다음 날까지 이어지는 근무는 390분을 추가합니다. 다음 날 같은 DIA의 ~ 기록이 있거나 당일 기준 계산이 자정을 넘으면 야간 기준을 적용합니다. 기준표에 명시된 퇴근시각은 우선합니다. ~ 날짜에는 전날 근무의 퇴근을 표시하고 근무시간을 중복 합산하지 않습니다. 사용자 지정 잠정 기준이며 변경 위치는 dist/core.js의 provisionalRestRule입니다.

## GitHub Pages 배포 준비
아직 온라인 배포하지 않았습니다.
1. GitHub에 빈 공개 저장소를 만듭니다.
2. 이 프로젝트 파일을 main 브랜치에 올립니다. 개인 사진, 실제 근무표, 백업은 올리지 마세요. dist/example.json은 가상 예시입니다.
3. 저장소 Settings → Pages → Source를 GitHub Actions로 선택합니다.
4. Actions의 Publish calendar를 실행합니다. 성공 후 표시되는 HTTPS 주소로 모바일에서 접속합니다.
5. 아이폰 Safari의 공유 → 홈 화면에 추가, 안드로이드 Chrome의 설치/홈 화면에 추가를 사용합니다.

## 데이터 보관과 제한
앱 코드만 공개되며 개인 일정은 각 브라우저에 저장됩니다. 브라우저 데이터 삭제나 기기 변경 전에 JSON 백업을 내려받으세요. 로컬 주소와 GitHub Pages는 서로 다른 저장소이므로 백업 복원으로 옮깁니다. 처음 접속은 인터넷이 필요합니다. 실제 iOS/Android 설치와 오프라인 동작은 실기기 확인이 필요합니다.
